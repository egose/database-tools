# Restore Operations

`mongo-unarchive` downloads an archive from a configured backend and restores it into MongoDB. `postgres-unarchive` downloads a PostgreSQL archive, validates its manifest and payload, and restores it into an existing PostgreSQL database.

## Restore Success Contract

`mongo-unarchive` treats a restore as successful only when `mongorestore` reports no top-level error and zero document-level failures.

If any document fails to restore, the command returns a nonzero exit status and reports the successful and failed document counts. Post-restore update operations are not applied after any top-level restore error or document-level restore failure.

The tool does not attempt transactional rollback of documents that were already restored before `mongorestore` reported the failure.

## Archive Extraction Limits

Restore commands extract only regular files and directories from `.tar.gz` backups.

The extractor rejects absolute paths, `..` traversal, symlinks, hard links, devices, FIFOs, and unsupported archive entries. Extraction is staged in a private directory and only moved into place after a full successful extract.

| Environment Variable                      | Default        | Description                                                      |
| ----------------------------------------- | -------------- | ---------------------------------------------------------------- |
| `MONGOUNARCHIVE__ARCHIVE_MAX_ENTRIES`     | `100000`       | Maximum number of archive entries to extract.                    |
| `MONGOUNARCHIVE__ARCHIVE_MAX_ENTRY_BYTES` | `34359738368`  | Maximum size in bytes for a single extracted file, 32 GiB.       |
| `MONGOUNARCHIVE__ARCHIVE_MAX_TOTAL_BYTES` | `274877906944` | Maximum combined size in bytes for all extracted files, 256 GiB. |

## Post-Restore Updates

Pass `--updates-file` to apply update operations after a successful restore.

```json
[
  {
    "collection": "users",
    "filter": {
      "email": { "$exists": true }
    },
    "update": [
      {
        "$set": {
          "email": {
            "$replaceOne": {
              "input": "$email",
              "find": "@",
              "replacement": "_"
            }
          }
        }
      }
    ]
  }
]
```

## PostgreSQL Restore Contract

`postgres-unarchive` selects only PostgreSQL managed backups under `postgres-archive/` by default. Pass `--object-name` for an explicit object, or omit it to select the latest eligible PostgreSQL archive under the configured prefix. When multiple restore backends are configured, pass `--storage-backend` to choose one.

Before starting `pg_restore`, the command downloads atomically, extracts defensively, and validates the PostgreSQL manifest and custom-format dump. Wrong-family archives, missing manifests, malformed manifests, and inconsistent payloads fail before target database changes are attempted.

The target database must already exist. The default invocation uses `pg_restore --exit-on-error` and does not pass `--clean` or `--create`. If `pg_restore` starts and then fails, partial database changes may already exist; the tool does not claim rollback.

```bash
set -eu
postgres-unarchive \
  --host=postgres.example.com \
  --user=<username> \
  --database=appdb_restore \
  --ssl-mode=require \
  --local-path=/var/backups/database-tools \
  --object-name="postgres-archive/<generated-name>.tar.gz"
```

```bash
set -eu
postgres-unarchive \
  --host=postgres.example.com \
  --user=<username> \
  --database=appdb_restore \
  --ssl-mode=require \
  --aws-region=us-east-1 \
  --aws-bucket=<bucket_name>
```
