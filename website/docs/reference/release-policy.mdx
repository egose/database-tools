# Release Policy

Tagged releases publish only after the exact tagged commit passes the release verification gate.

The release gate includes:

- Supply-chain consistency checks.
- `pnpm install --frozen-lockfile`.
- Go tests, race tests, and vet checks.
- `go mod verify`.
- `govulncheck` through the repository release script.
- Docker build checks.
- Container smoke checks for all four wrappers plus `pg_dump` and `pg_restore`.
- A containerized PostgreSQL archive/restore round trip.
- Cross-platform binary builds.
- Reproducible archive checks.

Published binary releases include SHA-256 checksums, an SPDX JSON SBOM, and GitHub artifact provenance attestations. Native release archives include the four Go wrappers and do not bundle PostgreSQL native clients; native PostgreSQL operations require compatible external `pg_dump` and `pg_restore` in `PATH`.

Container publication is scan-before-push: the workflow builds and scans a local image before authenticating to GHCR or publishing tags. The container image includes pinned PostgreSQL clients and verifies their versions before publication.

For the detailed policy, see [`docs/release-artifact-policy.md`](https://github.com/egose/database-tools/blob/main/docs/release-artifact-policy.md).
